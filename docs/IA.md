# IA.md — 정보구조 (Information Architecture)

이 문서는 앱의 화면/메뉴 구조를 정의한다. 실제 콘텐츠는 아직 채워지지 않았다.
항목은 실제 자료를 분석하면서 확장 가능하다 — 임의로 삭제하지 않는다
(`CLAUDE.md` 18. DELETE CAREFULLY).

## 홈 화면

처음 화면부터 복잡하게 만들지 않는다. 홈에는 크게 두 블록만 둔다.

### 1) 지금 바로 찾기 (검색창)

예시 질의:
- "고객 앞에서 질문해도 돼?"
- "정액권 이렇게 해도 돼?"
- "컴플레인 생겼어요."
- "시험 조건 뭐예요?"

### 2) 빠른 진입점

자주 찾는 것 / 오늘 처음 왔어요 / 고객 응대 / 업무·기술 / 식구 관계 /
성장·교육 / 운영 기준

## A. 처음 온 식구

새 식구가 들어왔을 때 보는 영역.

- 우리는 어떤 매장인가
- 처음 1주일에 알아야 할 것
- 처음 한 달 동안 해야 할 것
- 식구 호칭
- 하루 흐름: 출근 / 오픈 / 고객 맞이 / 식사 / 휴식 / 퇴근 / 마감 / 깨모닝 / 심연
- 교육: 질문하는 방법 / 모르는 게 있을 때 / 누구에게 물어볼까 /
  실수했을 때 / 피드백 받을 때
- 고객 앞에서 하지 말아야 할 행동
- 자주 쓰는 해피니언 용어 → **용어사전**으로 연결

### 용어사전 (예시 표제어 — 실제 정의는 미확정, 확인 필요)

깨모닝 / 심연 / 시면 / 고정고객 / 신규 / 소개 / 대체 / 실매출 / PCTP /
불사조 / 인간미 / 전문성 / 노력성 / 사심 / 밖으로의 의도

## B. 고객 관련

### 고객 오기 전
예약 확인 / 고객 기록 확인 / 이전 시술 확인 / 특이사항 / 지난 방문일 /
고객 이름 / 담당자 / 원하는 스타일 예상 / 준비할 것

### 고객 입장
인사 / 눈맞춤 / 반겨주는 태도 / 대기 안내 / 담당자가 바쁠 때 /
다른 식구가 대신 응대할 때

핵심은 행동 나열이 아니라 **기준**을 담는 것.
예: "어서오세요라고 말한다" (X) → "고객이 '나를 반기는구나'라고 느끼게 한다" (O)

## C. 상담

- 원하는 스타일이 명확한 고객 / 없는 고객("알아서 해주세요") / 사진 들고 온 고객
- 현실적으로 어려운 스타일 / 손상 때문에 안 되는 시술 / 가격이 예상보다 비싼 경우
- 커트 / 펌 / 염색 / 클리닉 / 남성 / 여성
- 첫 방문 / 기존 고객 / 컴플레인 이후 방문

각 상담 항목은 다음 구조를 따른다:

```
상황 → 고객이 진짜 원하는 것 → 확인해야 할 질문 → 주의할 것 →
추천 설명 → 최종 확인
```

## D. 시술 중

- 디자이너 ↔ 파트너 커뮤니케이션
- 고객 앞에서 질문 가능한 것 / 질문하면 안 되는 것
- 연화 / 중화 / 염색 터치 / 다운펌 / 드라이 / 샴푸 / 마사지 / 머리 말리기
- 고객에게 과정 설명하기 (전문성 전달)
- 대화: 고객이 조용히 있고 싶어 할 때 / 많이 이야기하고 싶어 할 때
- 시술 시간이 늦어질 때 / 실수했을 때

각 규칙 항목에는 **"Why?" 토글**을 둔다. 예:
"고객 앞에서 '연화 어떻게 발라요?'라고 묻지 않습니다." → [왜?] 누르면 이유 표시.

## F. 정액권·연회원권·결제

## G. 컴플레인

첫 화면 문구: "고객에게 문제가 생겼다면 여기부터 보세요."

```
1. 상황 파악
2. 고객 감정 확인
3. 사실 확인
4. 담당자가 할 수 있는 조치
5. 원장 보고 기준
6. 환불/재시술/보상 기준
7. 기록
8. 후속 연락
```

실제 사례 데이터베이스(`content/cases`, source_level: CASE)를 함께 둔다.
사례 항목 구조: 실제 사례 / 당시 대응 / 배운 점 / 현재 기준.

중요: "과거에 이렇게 처리했으니까 무조건 이렇게 한다"가 아니라
**"과거 사례"**로 명확히 표시한다 (CASE ≠ 공식 규칙).

## H. 파트너 성장

정신적 성장과 직업적 성장을 **섞지 않고** 분리한다.

### 정신적 성장
생각의 변화 / 피드백 수용 / 자기 이해 / 책임감 / 주도성 / 회복탄력성 /
관계 / 고객을 보는 태도

### 직업적 성장
기술 / 모델 수 / 시험 / 고객 응대 / 속도 / 정확도 / 콘텐츠 / 마케팅 /
디자이너 데뷔

기타: 파트너의 역할 / 디자이너가 되기 위한 조건 / 평균 기간 / 시험 /
모델 작업 / SNS / 블로그 / 게시물 / 인간미 / 전문성 / 노력성

## I. 디자이너 성장

신규 / 고정 / 소개 / 재방 / 객수 / 매출 / 실매출 / 고객 유지 / 상담력 /
기술 / 마케팅 / 고객 기록 / 인간미 / 전문성 / 노력성 / 후배 / 팀워크

성장 단계 구간 (예시, **출처 확인 전까지 게시 금지**):
0~50 / 50~100 / 100~180 / 180~260 / 260~320 / 320~400+

이 숫자들은 공식 기준(H1) / 사부님 가이드(H2) / 마곡점 운영 목표(M1) 중
무엇인지 **반드시 출처를 붙인다**. 출처가 확인되지 않으면 `review_needed`로
남기고 공개 게시하지 않는다.

## K. 애매한 상황 (Phase 4)

사용자가 상황을 서술하면 AI가 다음 구조로 답한다:

```
확인된 기준 → 관련 사례 → 현재 상황에 적용하면 → 선택지 → 리스크 →
추천 → 원장 판단 필요 여부
```

Phase 3(기본 앱)까지는 이 화면 자체를 만들지 않는다. IA 자리만 예약해둔다.
