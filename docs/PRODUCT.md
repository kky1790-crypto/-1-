# PRODUCT.md — 해피니언 마곡점 판단 시스템

## 목적

단순한 사내 규정집이 아니라, 해피니언 마곡점 식구들이 애매한 상황에서
스스로 판단할 수 있도록 돕는 '살아있는 운영·교육·판단 시스템'.

## 사용자

- 신입 식구 (막 입사한 파트너)
- 파트너 (인턴)
- 디자이너
- 리더

대부분 영업 중 매장에서 **휴대폰으로** 짧은 시간에 사용한다.

## 핵심 가치 (우선순위 순)

1. 정확성
2. 사용성
3. 출처 명확성
4. 유지보수 가능성
5. 모바일 접근성
6. 빠른 검색
7. AI의 환각 방지

## 앱이 동시에 만족해야 하는 10가지 조건

1. 급할 때 10초 안에 답을 찾을 수 있어야 한다.
2. 단순히 규칙만 보여주지 말고 왜 그런지도 이해할 수 있어야 한다.
3. 애매한 상황에서는 내부 기준을 기반으로 판단을 도와야 한다.
4. 없는 내용을 AI가 지어내서는 안 된다.
5. 해피니언 전체 기준 / 강서 기준 / 마곡점 기준 / 강윤 개인 의견을 절대 혼동하지 않는다.
6. 과거 기준과 현재 기준을 구분한다.
7. 공식 규칙과 추천을 명확하게 구분한다.
8. 실제 현장에서 휴대폰으로 빠르게 사용하기 편해야 한다.
9. 신입도 이해할 수 있을 정도로 쉽고 명확해야 한다.
10. 시간이 지나면서 계속 수정·추가 가능한 구조여야 한다.

## Phase 로드맵

앱부터 만들지 않는다. 순서를 건너뛰지 않는다 (`CLAUDE.md` 2장).

| Phase | 이름 | 내용 | 상태 |
|---|---|---|---|
| 0 | 프로젝트 기반 | 헌법 / Skills / Agents / 폴더 구조 | 완료 |
| 1 | Knowledge Inventory | 원자료를 규칙화하지 않고 수집·분류 (`docs/INVENTORY_MODEL.md`) | 진행 중 — 원자료 3건 등록, 전부 `pending_review` |
| 1.5 | 관리자 검수 시스템 | `review-admin/` — 사람이 직접 승인해야만 공개되는 검수 게이트 | 프로토타입 v1 완료 |
| 2 | Knowledge Base | 검증된 내용만 `content/` 실제 콘텐츠로 변환 | 미착수 |
| 3 | 기본 앱 | 문서 → 분류 → 검색 → 상세 → 출처 → 최근 변경 | 프로토타입 v1 (`app/`) — `review-admin`의 승인된 인벤토리를 직접 재노출, `content/` 파이프라인은 아직 없음 |
| 4 | AI Assistant | "이럴 땐 어떻게 해?" 애매한 상황 질의응답 | 미착수 |
| 5 | 운영 시스템 | 성장 현황/시험/모델 수/게시물 수/고객 수/체크리스트/교육 기록 등 마곡점 OS로 확장 | 미착수 |

Phase 1.5(review-admin)와 Phase 3(app)의 프로토타입 v1은 사용자가 실제로
써보고 구조/필드/표현을 확정하기 전 단계다. 사용자가 "이 구조 괜찮다"고
확인하기 전에는 원자료 3건 외 나머지를 추가하지 않는다.

### Phase 3 (기본 앱) 범위

- 홈 화면: 빠른 검색 + 자주 찾는 카테고리 진입점
- 카테고리별 목차 탐색 (`docs/IA.md` 기준)
- 검색 (제목/본문/동의어/키워드/질문형 문장)
- 상세 페이지: 본문 + 왜 그런가 + 출처 배지 + content_type(규칙/원칙/판단) 배지 + 상태 배지
- 최근 변경사항 피드
- 관리자 화면: 콘텐츠 등록/수정, `review_needed`/`conflict` 항목 확인

**Phase 3에는 넣지 않는 것**: AI 질의응답, "애매한 상황" 자동 판단,
자동 성장 단계 계산, POS/결제 시스템 연동.

### Phase 4 (AI Assistant) — Phase 3이 실사용으로 검증된 뒤 시작

- "이럴 땐 어떻게 해?" AI 질의응답 (`CLAUDE.md` 12. AI ANSWER STRUCTURE)
- 애매한 상황 질문 → 확인된 기준/관련 사례/선택지/리스크/추천/원장 판단 필요 여부

Phase 4를 먼저 붙이지 않는 이유: 내부 자료 구조(출처/성격/상태 태그, 검색)가
먼저 견고해야 AI가 그 위에서 찾고 조합하는 역할만 하게 만들 수 있다.
자료가 정리되지 않은 상태에서 AI부터 붙이면 AI가 틀린 답을 자연스럽게
말하는 앱이 된다.

### Phase 1(Knowledge Inventory)을 Phase 2보다 먼저 두는 이유

우리가 가진 원자료(대화, 경험)를 곧바로 "콘텐츠 문장"으로 정리하면 정리
과정에서 의미가 은근히 바뀔 위험이 크다 (`CLAUDE.md` 4장 PHILOSOPHY ≠ RULE).
그래서 먼저 `원문 → 주제 → 출처 → 현재성 → 확실성 → 충돌 여부`만 있는
그대로 펼쳐놓고(Phase 1), 사용자가 확정한 것만 Phase 2에서 정식 콘텐츠로
승격한다.

## 아직 결정되지 않은 것 (확인 필요)

- 기술 스택 (웹앱 / PWA / 네이티브 등) — 사용자와 논의 후 결정
- 실제 배포 방식 및 접근 권한 관리 방식
- 관리자 계정 체계
