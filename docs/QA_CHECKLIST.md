# QA_CHECKLIST.md — 완료 보고 전 체크리스트

`CLAUDE.md` 11장(DO NOT CLAIM COMPLETION EARLY)에 따라, 아래 항목을 모두
통과하지 못한 작업은 "완료"라고 보고하지 않는다. `/final-check` Skill을
실행하면 이 체크리스트 전체를 따라간다.

## 1. 기능 구현 검증
- [ ] 이번 요청의 요구사항을 체크리스트로 분해했는가
- [ ] 각 요구사항이 코드/콘텐츠에 실제로 구현되어 있는가
- [ ] 앱을 실제로 실행했는가
- [ ] 사용 가능한 자동 테스트를 모두 실행했는가
- [ ] lint / typecheck / build를 실행했는가
- [ ] 핵심 사용자 플로우를 직접 검증했는가
- [ ] 모바일 화면 폭에서 확인했는가
- [ ] 콘솔/런타임 오류를 검사했는가

## 2. 콘텐츠 무결성 (`/content-audit` 기준)
- [ ] `source_level`이 없는 콘텐츠가 없는가
- [ ] `status`가 없는 콘텐츠가 없는가
- [ ] `last_updated`가 없는 콘텐츠가 없는가
- [ ] K1/IDEA/CASE가 공식 기준처럼 작성된 곳이 없는가
- [ ] 같은 주제에 서로 다른 기준/숫자가 있는 곳이 없는가
- [ ] 오래된 기준이 최신 기준보다 우선 노출되는 곳이 없는가
- [ ] 내용 중복이 없는가
- [ ] 목차에는 있지만 콘텐츠가 없는 항목이 없는가
- [ ] 콘텐츠는 있지만 목차/검색에서 접근 불가능한 항목이 없는가
- [ ] 실제 사례와 정책이 혼동된 항목이 없는가

## 3. UX (`/ux-audit` 기준, 신입 파트너 관점)
- [ ] "오늘 처음 출근했는데 무엇부터 봐야 하지?" → 10초 내 도달 가능한가
- [ ] "고객 앞에서 질문해도 되나?" → 10초 내 도달 가능한가
- [ ] "정액권 규칙을 모르겠다" → 10초 내 도달 가능한가
- [ ] "컴플레인이 들어왔다" → 10초 내 도달 가능한가
- [ ] "누구에게 물어봐야 하는지 모르겠다" → 10초 내 도달 가능한가
- [ ] 데스크톱뿐 아니라 모바일 화면에서도 확인했는가

## 4. 회귀/안전 (`CLAUDE.md` 22, 23, 24)
- [ ] 기존 기능 중 이번 변경으로 깨진 것이 없는가
- [ ] 기존 콘텐츠/메뉴/데이터 필드/검색 키워드/링크가 사라지지 않았는가
- [ ] 데이터를 파괴적으로 변경하지 않았는가 (백업/롤백 방안 고려했는가)
- [ ] 정책/가격/시험 기준 등 의미 있는 내용을 사용자 승인 없이 바꾸지 않았는가

## 5. 최종 보고 형식
보고에는 다음을 포함한다: 구현한 것 / 검증한 것 / 발견한 문제 /
스스로 수정한 것 / 남아 있는 문제 / 관리자(사용자) 확인이 필요한 내용.

문제를 발견하면 보고만 하지 말고 안전하게 수정 가능한 것은 직접 수정하고
4번 항목부터 다시 검증한다. 사용자 판단이 필요한 문제만 "확인 필요"로 남긴다.
