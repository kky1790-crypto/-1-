# app/ — 식구용 앱 (Phase 3 프로토타입 v1)

`CLAUDE.md` Phase 로드맵의 Phase 3(기본 앱: 문서 → 분류 → 검색 → 상세 →
출처 → 최근 변경)를 실제로 만져볼 수 있는 최소 형태로 시작한 것이다.
**완성형이 아니라 프로토타입 v1** — 사용자가 직접 써보고 구조/표현/필드를
고친 뒤 콘텐츠를 늘려가는 것을 전제로 만들었다.

## 실행

```bash
cd app
npm install   # 이미 설치되어 있다면 생략 가능
npm start     # http://localhost:4100
```

(review-admin과 동시에 실행해도 포트가 다르다 — review-admin은 4000,
이 앱은 4100.)

## 구조

이 앱은 **자체 데이터 계층이 없다.** `review-admin/routes/publicApi.js`를
그대로 재사용한다 (`server.js` 참고) — 승인 권한과 공개 필터 로직
(`review-admin/src/publicFilter.js`)이 코드베이스에 단 하나만 존재하도록
하기 위해서다. `review_status: approved`인 인벤토리 항목만, 내부 전용
필드를 뺀 형태로 이 앱에 노출된다.

- 홈 화면: 검색 + scope 필터 칩(데이터에 실제로 존재하는 scope만 동적으로
  표시 — 항목이 늘어나면 칩도 자동으로 늘어난다) + 최근 승인된 내용 목록
- 상세 화면: content_type을 규칙/원칙/판단/철학/절차/지표/사례/의견/질문
  배지로 표시하고 그 의미를 함께 설명(`CLAUDE.md` 7장 RULE vs PRINCIPLE vs
  JUDGMENT), 출처·권위 상태를 항상 표시하며 출처/권위가 불확실한 항목은
  주의 문구를 눈에 띄게 보여준다
- 목록/카드 그리드는 항목이 30개, 100개로 늘어나도 그대로 쓸 수 있는
  구조(검색 + 필터 + 카드 그리드)로 만들었다 — 지금은 3개뿐이라 휑해 보일
  수 있다

## 지금 상태

`inventory/items/`에 원자료 3건이 있지만 **전부 `pending_review`(미검수)
상태**다. 즉 지금 이 앱을 열면 "아직 승인된 내용이 없습니다" 빈 화면이
보이는 게 정상이다. `review-admin`(`http://localhost:4000`)에서 검수·승인
해야 이 화면에 나타난다 — 그게 이 프로토타입의 핵심 포인트다: **승인
전에는 절대 여기 보이지 않는다.**

## 아직 구현하지 않은 것

- Phase 4(AI 질의응답), "애매한 상황" 질문 — 계획대로 아직 만들지 않음
- Phase 2(`content/`) 승격 파이프라인 — 지금은 인벤토리의 `approved`
  항목을 직접 재노출할 뿐, `content/`로 옮기는 절차는 별도(`docs/INVENTORY_MODEL.md`)
- 로그인/개인화, 최근 변경사항 전용 화면(지금은 목록이 승인일 기준
  정렬만 해줌), 관리자 전용 "검토 필요 항목" 뷰
- 실제 검색은 제목/요약/topics 텍스트 매칭만 한다 — 동의어/질문형 문장
  매칭(`CLAUDE.md` 11장)은 아직 없음
