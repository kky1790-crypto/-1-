description: 프로젝트를 완료했다고 보고하기 전 전체 검증
---

현재 작업을 완료했다고 가정하지 말 것.

지금부터 독립적인 QA 담당자처럼 프로젝트 전체를 검토한다.

1. 이번 요청의 원문을 다시 읽어라.
2. 요구사항을 체크리스트로 분해하라.
3. 각 요구사항이 코드에 실제 구현됐는지 확인하라.
4. 앱을 실행하라.
5. 사용 가능한 자동 테스트를 모두 실행하라.
6. lint/typecheck/build를 실행하라.
7. 핵심 사용자 플로우를 직접 검증하라.
8. 모바일 환경을 검토하라.
9. 콘솔 및 런타임 오류를 검사하라.
10. 누락된 콘텐츠가 없는지 검사하라.
11. 중복 콘텐츠를 찾는다.
12. 서로 충돌하는 정책을 찾는다.
13. 출처 레벨이 잘못된 정보를 찾는다.
14. AI가 추측해서 만든 정보가 없는지 검사한다.
15. 오래된 규칙이 최신처럼 노출되는지 검사한다.
16. 테스트용 가짜 데이터가 운영 데이터처럼 보이는지 검사한다.
17. 기존 기능 중 이번 변경 때문에 깨진 것이 없는지 검사한다.

문제를 발견하면 보고만 하지 말고,
안전하게 수정 가능한 문제는 직접 수정한다.

수정 후 4~17번을 다시 수행한다.

새로운 문제가 나오면 다시 수정하고 재검증한다.

치명적 문제 또는 사용자의 판단 없이는 해결할 수 없는 문제만
"관리자 확인 필요"로 남긴다.

검증되지 않은 상태에서 "완료"라고 하지 않는다.

참고: `docs/QA_CHECKLIST.md`에 이 점검을 체크리스트 형태로 정리해두었다.
